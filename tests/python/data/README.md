# Synthetic CFB fixture

`synthetic.cfb` is an original test fixture generated for ezexb under the MIT
license. It is a generic CFB v3 container, not an EXB drawing or vendor sample.
It has two storages, an empty stream, a 9,000-byte stream of `Z` bytes, and a
small binary stream named `/nested/日本語` with contents `b"small stream\x00\xff"`.

To regenerate at a new destination:

```sh
cargo run -p ezexb-core --example make_fixture -- /tmp/synthetic.cfb
```

CFB timestamps can differ between runs. Tests compare structure and payloads,
not whole-file hashes. Proprietary research files are not required by the tests.

## Additional stream-analysis fixture

`analysis.cfb` is an original synthetic CFB generated by
`cargo run -p ezexb-core --example make_analysis_fixture -- OUTPUT`.
It contains synthetic metadata, a 2×1 red/green BMP, a two-block compressed
payload, original LINE coordinates/attributes, typed property groups, and
simple/unsupported record headers. The unknown packed schema is `0x7777`;
`0x0101` is exercised as a supported property-bearing record. It was not authored by CAXA and
does not qualify EXB geometry compatibility. No third-party EXB bytes are copied.

## Recursive record fixtures

`schema3-33.cfb` and `schema3-37.cfb` are original synthetic containers generated
with `cargo run -p ezexb-core --example make_schema3_fixture -- OUTPUT 33` (or
`37`). They use observed build strings solely to select the framing profile;
they were not created by CAXA. They contain nested display records, a relation,
an absent cache, an unsupported tail/child schema, and a deliberately truncated
record. A top-level LINE and an unsupported CRX LINE test that cached LINEs are
kept separate. These fixtures contain no copied third-party drawing data.


## Stored-document fixtures

`document-10.cfb`, `document-18.cfb`, and `document-partial.cfb` are original,
handcrafted fixtures generated by `make_document_fixture`. They are not
CAD-authored EXB files. They exercise six stored geometry kinds, layer and
linetype references, a decoded text style, space membership, two block
definitions and an INSERT whose stored matrix intentionally disagrees with its components
(world expansion reports this). Layer width selection 2 explicitly selects the stored float.
The partial fixture adds an unknown record.

```sh
cargo run -p ezexb-core --example make_document_fixture -- document-10.cfb 10
cargo run -p ezexb-core --example make_document_fixture -- document-18.cfb 18
cargo run -p ezexb-core --example make_document_fixture -- document-partial.cfb 10 --unknown
```

The generator refuses to overwrite an existing file. Rust tests also synthesize
11, 15 and 16 branches, malformed references, cycles and budget boundaries.

## Additional entity fixtures

`entities-10.cfb` and `entities-18.cfb` extend the original stored-document fixtures
with POINT and six additional dimension classes. The build-10 fixture also adds
roughness, geometric tolerance, section and datum symbols, plus a part-number
callout with nested presentation and semantic item copies. Dimension/symbol tails
are deliberately unresolved synthetic bytes; strict reading must remain incomplete.
The build strings select parser branches and do not indicate CAD-authored fixtures.

```sh
cargo run -p ezexb-core --example make_entity_fixture -- entities-10.cfb 10
cargo run -p ezexb-core --example make_entity_fixture -- entities-18.cfb 18
```

No third-party EXB bytes are copied. The generator refuses to overwrite existing
files. Tests check typed Python/CLI data, nested record separation, world points,
approximate SVG output, and cumulative record/depth budgets.


## Remaining stored-object fixtures

`remaining-10.cfb` and `remaining-18.cfb` extend the original stored-document
fixtures with a diagnosed zero-radius/zero-basis ARC. Build 10 also contains a
View2D circular clip and BOM header/row presentations with original LINE/TEXT.
Build 18 adds general and hole-chart tables with sparse indices, Unicode cells,
block content and typed numeric properties. All bytes and text are original
synthetic data under the project MIT license, not CAD-authored exports.

```sh
cargo run -p ezexb-core --example make_remaining_fixture -- remaining-10.cfb 10
cargo run -p ezexb-core --example make_remaining_fixture -- remaining-18.cfb 18
```

The generator refuses overwrites. Tests check typed Rust/Python/CLI fields,
strict/partial diagnostics, cumulative limits, omitted view expansion and
single rendering of saved table/BOM presentations.
